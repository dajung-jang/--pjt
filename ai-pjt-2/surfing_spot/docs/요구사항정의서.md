# 요구사항 정의서 — Surf Lab (서핑 스팟 RAG 지식 서비스)

## 1. 도메인과 선택 조건 충족 근거

**도메인: 서핑 스팟(해수욕장)** — 해변을 고르고, 파도·이안류·서핑 안전에 대해 근거와 함께 묻는 서비스.

**선택 이유** : 평소 서핑을 취미로 하고 있어 서핑에 관련된 정보에 해변에 대해 알려주는 사이트를 만들어 보고 싶어 선정 했습니다.

| 조건 | 내용 |
|---|---|
| 항목 메타데이터 출처와 건수 | 공공데이터포털 「해양수산부_해수욕장정보목록」(수정일 2025-07-31) **277건**. 이용허락범위 제한 없음. 이름·지역이 함께 유일한 키. 서핑 스팟 4곳(죽도, 인구, 송정, 중문색달)은 유형을 "서핑 스팟"으로 직접 표시 |
| 외부 문서 출처와 이용 조건 | 한국어 위키백과(MediaWiki API). CC BY-SA 4.0. 근거 목록에 문서 제목과 원문 URL을 항상 표시. 호출 시 User-Agent 에 연락처를 넣고 호출 간격 0.5초, 429 응답 재시도 |
| 근거 없이 답하면 틀리거나 위험한 질문 (3개 이상) | ① "죽도에서 이안류에 휘말리면 어떻게 해야 해?" — 잘못 답하면 구조 요령이 틀려 위험 (위키 '이안류' 문서가 근거) ② "이안류와 연안류는 어떻게 달라?" — 용어를 섞어 답하기 쉬움 (위키 '파도' 문서가 근거) ③ "죽도해변은 길이와 너비가 얼마야?" — 항목 메타데이터에서만 알 수 있음 (근거 없이는 지어내기 쉬움) ④ "오늘 죽도 파도 높이 얼마야?" — 어떤 자료에도 없으므로 "확인되지 않는다"고 답해야 하는 질문 |
| 판단이 위험한 도메인인가 | **예.** 입수 판단은 안전과 직결된다. 화면 상단에 항상 표시하는 면책 문구: "서핑과 해수욕은 안전과 직결됩니다. 이 서비스의 답변은 전문가나 안전요원의 판단을 대신하지 않으며, 입수 전에 현장의 기상 상황과 안내를 반드시 확인하세요." |

### 범위와 한계
- 실시간 기상청·해양 API는 사용하지 않는다. 호출 조건·키 발급이 까다롭고 이번 과제의 핵심이 RAG이기 때문이다. 대신 "오늘 조건"을 사용자가 직접 입력하게 했다.
- 위키백과에는 해변별 서핑 난이도·안전 정보가 거의 없다(죽도·인구·중문색달은 자체 문서 없음). 그래서 해변 단위 안전 정보는 비워 두고, 공통 개념 문서(서핑, 파도, 이안류 등)와 항목 메타데이터를 근거로 쓴다. 서핑 전문 PDF는 심화 F2016으로 추가할 수 있다.

## 2. 항목 텍스트 설계 (2.2)

항목 1건을 `이름 / 지역 / 유형 / 규모 / 난이도 / 특징 / 주의사항` 순으로 라벨을 붙여 한 텍스트로 묶는다. 비어 있는 속성은 넣지 않는다.
이름과 지역을 넣어 "양양 해변"처럼 지역으로 찾을 수 있게 했고, 난이도·특징·주의사항은 채워지면 "초보에게 좋은 해변" 같은 조건 검색에 쓰인다.
현재는 서핑 스팟 속성이 대부분 비어 있어 속성 조건 검색은 제한적이다(한계).

### 도메인 특화 기능(F2010) 상세
사용자가 현장에서 본 **파도 높이, 바람 방향, 숙련도**를 입력하면, 이 조건을 질문 문장으로 풀어 위키 문서를 수집·검색하고 프롬프트 4로
"근거로 확인되는 고려사항 / 자료로 확인되지 않는 부분 / 입수 전 점검 순서"를 만든다.
- 근거에 없는 수치 기준(몇 m 이상 위험 등)을 만들지 않는다. 숙련도별 기준이 문서에 없으면 "확인되지 않는 부분"에 적는다.
- "입수해도 안전하다" 같은 단정을 쓰지 않는다.
- "입수 통제나 경보가 있다"를 체크하면 LLM 없이 입수하지 말라는 안내만 보여준다.

## 5. 화면 구성

- 상단: 제목, 면책 경고(항상 표시)
- 사이드바: 조건으로 찾기(F2011) → 항목 선택, 항목 메타 건수·색인 건수, 이 항목 대화 지우기, 대화한 항목 목록
- 본문: 선택 항목 정보 → 입수 판단 가이드(펼침) → 채팅. 답변 아래에 "답변에 사용한 근거 N건"(유형 라벨·제목·원문 링크)
- 안내: 색인 없음, 키 누락, 검색 실패, 인용된 근거 없음, 조건에 맞는 항목 없음
